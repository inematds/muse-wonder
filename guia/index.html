Em resumo

Em 12 de outubro de 2026 a Meta lançou dois modelos de inteligência artificial, o Muse Wonder e o Muse Wonder Full, feitos para trabalhar sozinhos por muito tempo em programação e tarefas de escritório. Este guia junta os números que conferimos nas fontes oficiais e independentes, mostra onde eles ganham e onde perdem do Claude Opus 5.5 e do GPT-6 Astra, e ensina a usar e a testar você mesmo. Serve para quem programa com agentes e quer decidir com prova própria, não com o gráfico de quem vende. Para ler, não precisa instalar nada.

O que saiu

Dois modelos, um milhão de tokens

Os dois leem 1.048.576 tokens de contexto, recebem texto, imagem, vídeo, áudio e PDF, e respondem só em texto.

🧠 Muse Wonder

Está na API da Meta (muse-wonder-1.0, em Preview), no Muse Code e no OpenRouter. Custa US$ 4 por milhão de tokens de entrada e US$ 20 de saída, o mesmo que o Opus 5.5.

🚀 Muse Wonder Full

A versão mais forte. Não tem API: só roda no Muse Code, o agente de terminal da Meta, nos planos Power (US$ 50/mês) e Maximum (US$ 200/mês).

🎯 Para quê

Trabalho longo e autônomo: programação em vários arquivos, agentes, uso do computador, direito e finanças. O antigo Muse Spark era o rápido e compacto.

⚠️ Antes de acreditar nos gráficos

  • A tabela principal é da própria Meta. O Personal Superintelligence Index, o MemoryBench e o FocusBench são internos: ninguém de fora consegue rodar.
  • Os concorrentes rodaram "no melhor esforço" da Meta, em configurações que a própria Meta admite que podem não ser as ideais para eles.
  • A Meta já se complicou com benchmark no Llama 4 (2025), quando mostrou no LMArena uma versão diferente da que liberou.
  • O mesmo teste muda de número conforme a fonte: no Harvey (jurídico) a Meta dá 13,1 ao Full e a Vals dá 21,67%, com outra versão do teste.
  • Segurança: o model card diz que, sem mitigação, a Meta não descarta risco alto em química e biologia; com os filtros, tudo fica em "moderado ou menor". O relatório completo de segurança ainda não saiu.
  • Privacidade: as assinaturas do Muse Code começam no Contributor mode (seu código pode treinar modelos futuros). Dá para desligar, mas não desfaz o que já foi enviado.
Como usar

API da Meta, OpenRouter ou Muse Code

O Wonder roda por API (paga por uso) e no Muse Code. O Full só no Muse Code, com assinatura Power ou Maximum. Pagar a assinatura não dá acesso ao Full por API.

1

Crie a conta e a chave na Meta Model API

Entre em dev.meta.ai, crie a conta de desenvolvedor e gere uma chave. Guarde-a numa variável de ambiente, nunca no código.

export MODEL_API_KEY="sua-chave"
curl -s https://api.meta.ai/v1/models -H "Authorization: Bearer $MODEL_API_KEY"  # confere se o muse-wonder-1.0 aparece
2

Chame o Wonder com o SDK da OpenAI

O endpoint Chat Completions é compatível com o formato da OpenAI: troque o base_url e o nome do modelo. Para tarefas longas com ferramentas, a Meta recomenda a Responses API (POST /v1/responses).

import os
from openai import OpenAI

client = OpenAI(base_url="https://api.meta.ai/v1", api_key=os.environ["MODEL_API_KEY"])
r = client.chat.completions.create(
    model="muse-wonder-1.0",
    reasoning_effort="high",   # vai de "minimal" a "max"; "max" NÃO vira o Full
    messages=[{"role": "user", "content": "Explique o que este repositório faz."}],
)
print(r.choices[0].message.content)
3

Ou use pelo OpenRouter

O Wonder está no OpenRouter como meta/muse-wonder, com o mesmo preço (US$ 4 / US$ 20) e 1M de contexto. O Full não está lá.

client = OpenAI(base_url="https://openrouter.ai/api/v1", api_key=os.environ["OPENROUTER_API_KEY"])
client.chat.completions.create(model="meta/muse-wonder", messages=[...])
4

Instale o Muse Code (o agente de terminal da Meta)

É o caminho para o Wonder Full. Rode na pasta do projeto, confie na pasta e faça login pelo navegador ou com a chave. Os planos ficam em dev.meta.ai/docs/muse-code/subscriptions.

curl -fsSL https://dev.meta.ai/install.sh | sh        # Linux e macOS
irm https://dev.meta.ai/install.ps1 | iex              # Windows (PowerShell)
muse --version
cd meu-projeto && muse                            # escolha o modelo Wonder na sessão
muse exec "rode os testes e corrija o que falhar"   # sem tela (CI), com META_API_KEY
Como testar

O teste que vale é no seu código

Benchmark é média de tarefas dos outros. Para decidir, compare na sua base, com as mesmas condições. Defina antes o que vai comparar: Wonder × Opus por API (mesmo preço) ou Muse Code + Full × Claude Code + Opus (assinatura × assinatura).

1

Escolha 3 a 5 tarefas reais, cada uma com teste

Um bug com teste que falha, um recurso médio, uma refatoração em vários arquivos e, se puder, uma tarefa longa (horas). Sem teste não há como dizer quem acertou.

2

Congele o ponto de partida

Mesmo commit, uma cópia limpa para cada agente, o mesmo pedido, e os testes de verificação fora do alcance dele.

git worktree add ../teste-wonder <commit>
git worktree add ../teste-opus   <commit>
# mesmo arquivo de pedido nos dois; mesmas regras (AGENTS.md / CLAUDE.md equivalentes)
3

Mesmas condições, 3 rodadas cada

Mesmo nível de raciocínio, mesmo limite de tempo, mesmas ferramentas e permissões. O resultado varia de uma rodada para outra; três rodadas dão uma média honesta.

4

Meça três coisas (e anote o resto)

Tempo de relógio, custo (tokens de entrada, cache e saída × preço) e testes passando, incluindo a suíte inteira para pegar regressão. Anote também quantas vezes você precisou intervir.

5

Revise o diff às cegas e decida

Peça a outra pessoa (ou a um terceiro modelo) para avaliar a qualidade sem saber quem fez. Compare taxa de acerto, custo por tarefa resolvida e tempo. Lembre: o Wonder é forte em tarefa longa e fraco em conhecimento puro.

🧪 Benchmarks públicos que dá para rodar

Terminal-Bench (tarefas em contêineres), SWE-bench Verified/Pro (local com Docker), ProgramBench (com mini-swe-agent) e OSWorld (uso do computador). Procure a página oficial de cada um para as instruções. O Personal Superintelligence Index e o MemoryBench são internos da Meta e não dá para rodar.
